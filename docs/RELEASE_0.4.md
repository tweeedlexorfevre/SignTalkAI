# SignTalk 0.4 — облачный ИИ и новый интерфейс

Дата: 17.11.2026. Готовая сборка: `web/dist`. Запуск: `preview-windows.cmd`, адрес http://localhost:5331/.

## Изменения

- Главная страница теперь содержит камеру и редактор сообщения рядом. Убраны большой вводный блок, конкурсные подписи и длинное описание моделей.
- Отдельные разделы: «Общение», «Жесты», «Сбор примеров», «Помощь» и настройки. На телефоне навигация закреплена внизу. Объяснения, ограничения и авторство доступны в помощи.
- Быстрые фразы, копирование и крупный показ сообщения. Ничего не озвучивается автоматически. Язык интерфейса и выходного текста независимы.
- Запись 5-секундного видео без аудио, 3 секунды подготовки, просмотр и отправка после отдельного согласия. Можно загрузить WebM/MP4 до 12 МБ и 15 секунд; звук загруженного файла также может передаваться провайдеру.
- Google Gemini подключён через локальный Node-сервер. Основная модель — `gemini-4-argon`, в настройках доступны альтернативы. Модель не меняется скрытно при ошибке. На старой модели можно продолжить в режиме «На устройстве».
- В облачном режиме не загружаются локальные ONNX-модели и MediaPipe. Сборщик, помощь, словарь и настройки загружаются отдельно по запросу.

## Ключ и запуск

Ключ находится в **`.env.local` в корне проекта**, читается сервером при запуске и не передаётся браузеру. Этот файл игнорируется Git и исключён из релизного архива. В архиве есть `.env.example` с пустым шаблоном. Для запуска облачного режима из новой распакованной копии нужно создать собственный `.env.local`.

```dotenv
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-4-argon
```

После замены ключа перезапустите `preview-windows.cmd`. Подключение проверяется кнопкой в настройках: она отправляет маленький текстовый запрос. Смена модели в интерфейсе действует на следующие запросы.

Для разработки используйте `start-windows.cmd` / `cd web; npm.cmd run dev`. Скрипт запускает Vite на 5330 и локальный API на 5331 либо использует уже запущенный API. Один и тот же датасет в IndexedDB требует одинакового адреса, порта и браузера — рекомендуем собирать примеры на 5331.

## Проверено

- Windows, Node.js 24.14.1. Линтер, TypeScript и production build успешно.
- 150 unit-тестов приложения, 5 тестов серверного API, 9 E2E-сценариев Chromium/телефон.
- Последний предоставленный ключ: реальный текстовый запрос к **Gemini 4 Argon**, HTTP 200.
- Реальный запрос видео через браузер → локальный прокси → Google → ответ: **HTTP 200, 5610 мс**, результат `uncertain` с пустым текстом. Видео было синтетическим однотонным кадром без человека, а не реальным жестом. Это подтверждает интеграцию и один корректный отказ, не качество распознавания.
- С искусственной камерой и заглушкой ответа проверены запись, отсутствие отправки без согласия, ручной перенос результата, ошибка квоты, отмена, отбрасывание позднего ответа, освобождение камеры после навигации, быстрые фразы, полноэкранное сообщение.
- Axe WCAG 2 A/AA и 2.1 AA: главная RU 1365×1000, KZ 375×812, RU 844×390 dark; настройки 375×812; помощь KZ dark 1280×900; словарь и сборщик 375×812. Нарушений, ошибок JavaScript и горизонтального переполнения в этих состояниях нет.
- В серверных тестах проверены блокировка стороннего Origin, отсутствие ключа в ответах, требование согласия, тип контейнера видео, разбор JSON, ошибки квоты/перегрузки/ключа. Адрес Google фиксирован; пользователь не может задать сторонний API endpoint.

## Ограничения

Точность облачной модели на живых KRSL/РЖЯ, разные участники и освещение **не измерены**. Универсальная видеомодель может ошибаться или выдумывать смысл; её ответ показан как вариант, без ложных процентов уверенности и без автоматической речи. Следующая содержательная проверка — размеченные видео носителей и неизвестные жесты с независимым контролем.

Приложение не пишет видео на диск сервера, устанавливает `store: false` для взаимодействий Gemini и не ведёт журнал содержимого. Это не отменяет условий обработки и хранения данных самим Google. Облачные вызовы требуют интернета, доступной квоты и могут тарифицироваться провайдером. В этой сессии проверка выполнена на коротких технических входах.

NVDA, реальный пользовательский сценарий с незрячим человеком, прослушивание TTS и поддержка казахского ASR не проверены. Локальные модели, их веса и лицензии сохранены. Код и документация этого релиза подготовлены при помощи Codex; новые модели не обучались.

## Структура

- `web/src/App.tsx` — композиция страниц и общие настройки.
- `web/src/cloud/` — захват, согласие, отмена и клиент локального API.
- `web/src/pages/` — помощь, словарь и настройки с отдельной загрузкой.
- `web/src/product.css` — визуальные токены и адаптивный интерфейс поверх общих компонентов.
- `server/cloud.mjs` — ограниченный прокси к Google; `cloud.test.mjs` — его проверки.
- `tools/serve.mjs` — статическая сборка и API на loopback; `tools/dev.mjs` — совместный запуск разработки.

Документация Google: [Interactions API](https://ai.google.dev/api/interactions), [видео](https://ai.google.dev/gemini-api/docs/video-understanding), [ключи](https://ai.google.dev/gemini-api/docs/api-key).
