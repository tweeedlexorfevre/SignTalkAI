# Проверки релиза

Среда реализации: Linux, Node.js 24.22.1. Пользовательский компьютер Windows к этой среде не подключён.

## Автоматически проверено

- `npm ci`: установка из lockfile.
- `npm run typecheck`: строгая проверка TypeScript.
- `npm test`: 139 тестов; включая исходные тесты ML/сессии/хранилища и новые проверки входных контрактов.
- `npm run build`: production-сборка со всеми локальными ресурсами.
- `npm run verify:models`: настоящий ONNX Runtime Web / WASM, 10 выходов KRSL и 1599 РЖЯ. Для KRSL использован реальный сохранённый тестовый вектор; для РЖЯ — нулевой RGB-тензор только как проверка операторов и формы, не качества распознавания. В проверенной среде примерно 12 мс и 4765 мс соответственно. Это не общая гарантия задержки на Windows.
- Численная сверка sklearn→ONNX: ошибка вероятностей около 3,3e-7.
- Сверка Python/TypeScript-препроцессоров KRSL на исходных координатах.
- Проверка RGB/255 и порядка каналов/времени для Easy Sign.

## Проверено через интерфейс браузера

- RU/KZ переключает интерфейс, включая камеру, меню, описание моделей, диалог и ограничения. Язык сохраняется при перезагрузке.
- Язык выходного текста выбирается независимо от интерфейса и модели.
- KRSL загружает настоящую модель; контрольная запись «где» распознана в браузере. Источник результата явно обозначен как запись, не камера.
- Выбранная гипотеза переносится в поле текста, без автоматического озвучивания.
- Easy Sign загружается в браузере как отдельный профиль.
- ASL-профиль и словарь проверяются отдельно от местного.
- Разрешение облачного ASR по умолчанию выключено.

`web/e2e/app.spec.ts` обновлён под новый интерфейс. Отдельный Playwright-прогон в этой среде не запускался; он не включён в число 139 unit-тестов. Камера и NVDA не симулировались для заявления о пользовательской доступности.

## Перед показом на Windows

1. Запустить `preview-windows.cmd` в Chrome/Edge, проверить камеру и освобождение камеры при смене модели/скрытии вкладки.
2. Снять независимые записи местных носителей и отдельно измерить новую камеру. Старые координаты и новая камера — разные условия.
3. Проверить плохое освещение, две руки, левую руку, пустой кадр и жесты вне словаря. Зафиксировать ложные уверенные ответы.
4. Провести клавиатурный проход и тест NVDA с реальным пользователем; проверить фокус, подписи, отчёты о состоянии и отсутствие лишних повторов.
5. Проверить голос Windows ru-RU/kk-KZ. При отсутствии голоса оставить текст или установить подходящий голос из официальных настроек Windows.
6. Проверить Web Speech API и явно обозначить облачный канал, если он используется.

Непроведённые проверки не считаются успешными.
