# SignTalk 0.7 — мессенджер и видеозвонки с переводом жестов

## Что умеет прототип

- **Аккаунты.** Регистрация (имя, логин, пароль), вход по логину или по уникальному ID. Каждый получает ID вида `ST-7KQ2MX` (без похожих символов 0/O/1/I).
- **Несколько устройств.** Один аккаунт открыт на телефоне, ноутбуке и планшете одновременно. Сообщения приходят на все устройства. Звонок звонит на всех, отвечаете на одном — на остальных звонок гаснет. В «Профиле» виден список устройств (браузер · ОС, в сети / был(а)), любое устройство можно отключить.
- **Поиск по ID и контакты.** В «Чатах» введите ID собеседника (регистр и дефис не важны: `st-7kq2mx`, `7KQ2MX`) или его логин.
- **Переписка в реальном времени.** Доставка через WebSocket, «печатает…», «доставлено / прочитано», счётчики непрочитанных, история с подгрузкой, быстрые фразы RU/KZ.
- **Видеозвонок (WebRTC).** Вызов → звонок с вибрацией и мигающим экраном (для глухих) → ответ/отклонение. Микрофон, камера, пропущенные/отклонённые/завершённые звонки записываются в чат.
- **Перевод жестов во время звонка.** На вашем устройстве MediaPipe отслеживает руки в том же видео, что уходит собеседнику; модель **KRSL · 10 жестов** (или ASL · 250) распознаёт жест, когда вы опускаете руки. Уверенный результат сразу уходит собеседнику крупным субтитром и сохраняется в чате как «Перевод жеста». Неуверенный — показывается вариантами, их можно отправить нажатием. Собеседник видит индикатор «показывает жест…».
- **Дактиль (алфавит РЖЯ) во время звонка.** В панели перевода выберите модель «Дактиль РЖЯ · алфавит» (Bukva, 33 буквы). Показывайте слово по буквам — собеседник видит буквы сразу, живым субтитром. Опустите руку примерно на 2 секунды — слово отправляется как «Перевод жеста». Слово можно отправить раньше, стереть букву или очистить. Модель работает по пикселям камеры без MediaPipe; казахские буквы Ә, Ғ, Қ, Ң, Ө, Ұ, Ү, Һ, І не распознаются.
- **Для слышащего собеседника:** «Субтитры моей речи» (речь → текст, Chrome/Edge) и «Озвучивать жесты и сообщения собеседника» (синтез речи).
- Видео не отправляется на сервер: распознавание идёт на устройстве, через сервер проходят только сигналы соединения, субтитры и сообщения.

## Архитектура

```
Браузер A ──HTTPS (REST /api)──┐                ┌── Браузер B
          ──WebSocket (/ws)────┤ server/app.mjs ├── WebSocket
                               │  SQLite-файл   │
          ◄──── аудио/видео WebRTC (P2P, при необходимости через TURN) ────►
```

| Файл | Назначение |
|---|---|
| `server/schema.sql` | SQL-схема: `users`, `sessions` (устройства), `contacts`, `messages`, `calls` |
| `server/db.mjs` | Доступ к SQLite (встроенный `node:sqlite`, ничего не компилируется) |
| `server/auth.mjs` | scrypt-хеши паролей, токены (в БД хранится только SHA-256), ID, валидация |
| `server/api.mjs` | REST API |
| `server/realtime.mjs` | WebSocket-хаб: онлайн-статус, доставка, сигналинг звонков, субтитры |
| `server/app.mjs` | Один процесс: сайт + API + WebSocket + облачный прокси Gemini |
| `web/src/messenger/` | Клиент: `store.ts` (аккаунт/чаты/WS), `call.ts` (WebRTC), `translator.ts` (жесты в звонке), страницы и экран звонка |

### REST API (все, кроме регистрации и входа, — с `Authorization: Bearer <token>`)

| Метод и путь | Что делает |
|---|---|
| `POST /api/auth/register` `{username, displayName, password}` | Создать аккаунт → `{token, user, sessionId}` |
| `POST /api/auth/login` `{login, password}` | Вход по логину или ID с нового устройства |
| `POST /api/auth/logout` | Выйти на этом устройстве |
| `GET/PATCH /api/me` | Профиль / сменить имя |
| `GET /api/devices`, `DELETE /api/devices/:id` | Устройства аккаунта / отключить устройство |
| `GET /api/users/lookup?q=ST-XXXXXX` | Найти по ID или логину |
| `GET/POST /api/contacts`, `DELETE /api/contacts/:id` | Контакты с последним сообщением, непрочитанными и онлайн-статусом |
| `GET/POST /api/chats/:id/messages` | История (`?before=&limit=`) / отправить `{kind: text\|sign\|speech, body}` |
| `POST /api/chats/:id/read` `{upTo}` | Отметить прочитанным |
| `GET /api/ice` | STUN/TURN-серверы для WebRTC |

WebSocket `/ws`: первое сообщение `{type:"auth", token}`; далее события `presence`, `message:new`, `read`, `typing`, `contact:added`, `call:incoming/ringing/accepted/taken/signal/caption/ended`, `session:revoked`.

## Запуск на своём компьютере

```sh
npm ci                 # зависимости сервера (в корне проекта)
npm --prefix web ci    # зависимости сайта
npm --prefix web run dev
```

Откройте http://localhost:5330/. Чтобы проверить разговор двух людей на одном компьютере, откройте второй профиль браузера (или окно инкогнито) — у каждого свой вход. Готовая сборка: `npm run build && npm start` → http://localhost:5331/.

Камера и микрофон работают только на `https://` или `localhost`. Для проверки с телефона используйте развёрнутую на Render версию (там HTTPS).

## Деплой на Render.com

1. Загрузите проект в GitHub.
2. Render → **New → Blueprint** → выберите репозиторий. Render прочитает `render.yaml`:
   - сборка `npm ci && npm run build`, запуск `npm start`, проверка `/healthz`;
   - диск `/var/data` для файла базы `signtalk.db` (нужен платный план Starter).
3. **Бесплатный план:** удалите блок `disk` из `render.yaml` (и `plan: starter`). Всё работает, но база стирается при каждом деплое/перезапуске, а сервис засыпает после простоя (первое открытие ~1 мин).
4. Необязательно — **TURN-сервер** (`TURN_URLS`, `TURN_USERNAME`, `TURN_CREDENTIAL`). Без него видео соединяется напрямую через STUN Google; в ~10–20 % сетей (мобильный интернет, корпоративные NAT) звонок без TURN не установится. Подойдёт свой coturn или облачный TURN (Twilio, Metered, Cloudflare).

## Ограничения прототипа

- Распознавание жестов экспериментальное: KRSL — 10 отдельных слов (где, как, какой, когда, который, кто, куда, сколько, что, зачем), ASL — 250 слов американского жестового языка. Это не перевод свободной жестовой речи.
- Звонки один на один; групповых звонков нет.
- Один процесс сервера (SQLite + состояние звонков в памяти) — для прототипа и десятков-сотен пользователей. Для масштабирования нужен PostgreSQL и общий брокер (Redis) для WebSocket.
- Восстановления пароля нет (нет e-mail).
