# Сбор примеров SignTalk AI

Экран **«Сбор примеров»** отделён от распознавания и персональных ASL-прототипов. Запись новых классов не меняет веса моделей. Для расширения словаря потребуются обучение и независимая оценка.

## Как записывать

1. Откройте готовую сборку через `preview-windows.cmd`, затем http://localhost:5331/. Для всех записей используйте один браузер и один адрес: хранилища портов 5330 и 5331 различаются.
2. Объясните участнику состав сохраняемых данных. Включайте согласие только после его разрешения. Оно разрешает локальную запись координат и выгрузку файла; передачу и публикацию согласуйте отдельно.
3. Выберите язык **набора**, укажите постоянный идентификатор класса, названия RU/KZ, псевдоним участника и сессию. Один человек должен иметь одинаковый псевдоним во всех файлах. Не вводите ФИО.
4. Включите камеру и дождитесь работы трекера. Держите руки в кадре, обеспечьте хорошее освещение. Нажмите «Записать пример»: 3 секунды подготовки и 2,5 секунды захвата.
5. Просмотрите движение сохранённых точек. Убедитесь, что сам жест и его название верны. Только затем сохраните пример. Повторяйте несколько раз, меняя условия умеренно.
6. Для сохранённой записи доступны просмотр, исправление метки, удаление и повтор. При повторе старая запись заменяется только после успешного сохранения новой.
7. Регулярно нажимайте «Экспорт JSON». Очистка данных браузера удаляет локальное хранилище. Лимит — 200 примеров на адрес; сохраните выгрузку до очистки.

Исходное видео, аудио, лицо и поза тела **не сохраняются**. Экспортируются только руки и число обнаруженных поз. MediaPipe Holistic вычисляет и другие точки для общего приложения, но сборщик отбрасывает их. Отображение координат зеркальное, сохранённые координаты — исходные, без отражения. Записи не отправляются на сервер. Псевдоним сам по себе не гарантирует анонимность.

Остановка камеры, уход с экрана, скрытие вкладки и отзыв согласия отменяют текущий захват. Несохранённый черновик теряется при уходе с экрана или перезагрузке. Отзыв согласия останавливает камеру и убирает черновик, но уже сохранённые записи нужно удалить отдельно.

## Формат

Версия: `signtalk.hands.v1`. Машиночитаемая схема: [dataset-schema.json](dataset-schema.json). Контракт и дополнительная проверка — `web/src/dataset/schema.ts`.

| Поле записи | Содержание |
|---|---|
| `id`, `recordedAt` | UUID записи и дата UTC |
| `label` | `language`: krsl/rsl/asl; `classId`; названия `ru`, `kk` |
| `participantId`, `sessionId` | Псевдоним человека и сессия захвата |
| `consent` | Версия текста согласия, время подтверждения, разрешённый локальный сценарий |
| `camera` | Размер исходного кадра и частота из настроек видеодорожки, если доступна |
| `tracker` | Библиотека, версия, CPU/GPU, набор признаков, имена моделей MediaPipe |
| `coordinates` | `mediapipe-normalized-xyz-unmirrored` |
| `featureVersion` | `raw-hands-xyz-v1`: сырые точки, без KRSL-нормализации |
| `frames` | Последовательность `{tMs, left, right, poses}` |
| `quality` | Число кадров, покрытие руками, фактическая частота, наибольший временной разрыв |

`left` и `right` — 21 точка в порядке MediaPipe, каждая `[x,y,z]`. Отсутствующая точка — `null`, полностью отсутствующая рука — `null`. Нули означают реальные координаты и не используются для заполнения пропусков. `x/y` нормализованы относительно исходного кадра; `z` — глубина MediaPipe относительно руки, не физические метры и не общая мировая система двух рук.

`tMs` — время захвата кадра относительно начала записи в миллисекундах, до отправки в worker. Последовательность строго возрастает. Кадры до начала захвата и после 2500 мс, повторы и некорректные временные метки исключаются. Реальная частота может быть ниже запрошенной: worker обрабатывает один кадр, остальные пропускает. Максимум 180 кадров. В конце окна ещё обрабатываемый кадр может не попасть в запись.

## Контроль качества

Сохранение доступно при минимум 12 кадрах с полностью обнаруженной хотя бы одной рукой; такие кадры должны составлять минимум 60% последовательности. Нужны фактические 5 FPS или больше и разрывы не более 600 мс, включая края окна. Наличие нескольких обнаруженных поз вызывает отказ. Holistic обычно отслеживает одного человека, поэтому эта проверка **не гарантирует** обнаружение всех посторонних людей: записывайте одного участника.

Это эвристики технического качества. Они не проверяют правильность жеста, язык, перевод или юридическую достаточность согласия. Повреждённые записи не удаляются автоматически; при ошибке сохранения черновик остаётся доступен. JSON Schema проверяет структуру; код дополнительно проверяет порядок времени и заново вычисляет качество.

## Для будущего обучения

Сохраняйте одинаковый `classId` для одной лексемы внутри одного жестового языка. Участник не должен встречаться одновременно в train, validation и test. Разделяйте людей **до** подбора параметров и обучения скейлера. Добавьте неизвестные жесты и обычные движения для оценки отказов; текущий экран предназначен для отдельных размеченных жестов.

Для воспроизведения KRSL-признаков из сырых кадров выбирайте полные руки, берите x/y, затем применяйте `krslFeatures` из `web/src/ml/krsl-features.ts`. Существующий `tools/train_krsl.py` пока читает старые Absolute TXT и **не импортирует этот JSON напрямую**. Для последовательностной модели используйте временные метки и маски отсутствующих точек; ресемплинг и интерполяцию нужно версионировать отдельно. Этот формат не подходит для обучения исходной RGB-модели Easy Sign без видео.

Новые записи носителей в этой сессии разработки не собирались. Синтетические тесты интерфейса не являются обучающим корпусом и не подтверждают точность распознавания.
