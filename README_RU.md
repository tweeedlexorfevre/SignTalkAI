# SignTalk AI — запуск на Windows

Задача приложения — распознать отдельный жест, получить текст RU/KZ и при необходимости озвучить его человеку, не знающему жестового языка. Переписка и субтитры — дополнительные инструменты. Модели KRSL / РЖЯ / ASL и облачное распознавание остаются экспериментальными; точный перевод свободной жестовой речи не обеспечен.

## Запуск

1. Установите **Node.js 24 LTS** с https://nodejs.org/ (вместе с npm). Git нужен только для обновления исходников.
2. Распакуйте весь архив, например в `C:\Projects\SignTalkAI`. Не открывайте `index.html` двойным щелчком.
3. Запустите `start-windows.cmd` в корне. При первом запуске он установит npm-зависимости. Дождитесь сообщения Vite и откройте **http://localhost:5330/** в Chrome или Edge.
4. Откроется **«Распознавание жестов»**. Начните с **KRSL · 10 жестов** и вкладки **«Словарь»**. Интерфейс переключается кнопками **ҚАЗ / РУС**, язык результата выбирается отдельно. Камера и отправка в облако включаются по действию пользователя.

Вручную, в PowerShell:

```powershell
cd C:\Projects\SignTalkAI\web
npm.cmd ci
npm.cmd run dev
```

Если порт 5330 занят, закройте предыдущий сервер или в другой консоли используйте `npm.cmd run preview:ready` для готовой сборки на http://localhost:5331/. Остановка: Ctrl+C в окне сервера.

В архиве есть модели и готовая папка `web/dist`. Для готовой сборки нужен Node.js, но переустановка библиотек не требуется: `preview-windows.cmd`. Скрипт обслуживает сайт, API мессенджера и WebSocket только на 127.0.0.1; при первом запуске он один раз установит зависимость сервера (`npm ci` в корне). При использовании готовой сборки интернет не нужен для загрузки моделей; голос браузера и распознавание речи могут требовать интернет. Для разработки `npm ci` нужен интернет.

## Какие модели действительно подключены

| Выбор | Реальное распознавание | Выход RU/KZ |
|---|---|---|
| Казахстан · KRSL | Наша небольшая MLP-модель, обученная на публичных координатах рук KRSL20 из репозитория kurshakuz. **10 лексических жестов**, без различения вопроса и утверждения по мимике | Все 10 слов переведены на оба языка |
| Русский жестовый · Easy Sign | Исходная S3D ONNX-модель Easy Sign, 1598 жестовых классов и технический класс `no` | Русские подписи полностью; 132 из 1599 подписей имеют казахский перевод, остальные явно показываются как RU |
| Американский · ASL | Исходная GestureSign ONNX-модель, 250 изолированных ASL-жестов | Все 250 подписей переведены RU/KZ. Это **ASL**, а не местный жестовый язык |

Переводы подписей — рабочая редакция, их нужно согласовать со специалистом перед публичной демонстрацией.

## Проверка без камеры

В KRSL откройте **«Словарь и проверка» → «Контрольная запись без камеры» → «Распознать записанный пример»**. ONNX-модель выполнит настоящее вычисление на заранее сохранённых признаках тестового участника. Интерфейс явно пишет, что это записанный пример, а не камера. На один класс взят первый файл по пути, а не специально отобранный удачный результат.

В ASL есть исходные примеры движения точек, проходящие через распознаватель, тренировка слов и персональные жесты. Персональные примеры в IndexedDB не являются обученной моделью местного языка.

## С камерой

- KRSL: включить камеру, дождаться точек рук, нажать «Записать жест». После отсчёта 3 секунды показать один жест в течение 2,3 секунды. Нужны хорошее освещение и чётко видимые руки. Результат выбрать из гипотез.
- РЖЯ: включить камеру, нажать запись, после отсчёта показать один жест. Модель получает 32 RGB-кадра 224×224, приблизительно за 1,1 секунды; вычисление на слабом ПК может быть медленным.
- ASL: отдельные жесты сегментируются автоматически; опускание рук завершает жест.
- При смене модели, скрытии вкладки и закрытии страницы камера останавливается. Низкий балл может вызвать отказ, но неизвестные жесты всё равно могут ошибочно распознаваться как известные.

## Чтение по губам (эксперимент)

На странице **«Распознавание»** вверху есть две кнопки: **«Язык жестов»** и **«Чтение по губам»**. Во втором режиме вы включаете камеру, нажимаете «Начать запись», беззвучно произносите фразу и нажимаете «Стоп». Текст появится справа, его можно перенести в сообщение.

- Модель: **Auto-AVSR** (через проект Chaplin), понимает **только английский** и свободные фразы. Около 80% слов верно в хороших условиях, на веб-камере хуже.
- Видео не уходит в интернет: его обрабатывает Python-сервис на этом же компьютере (`lipread/server.py`, порт 5340), Node-сервер проксирует к нему `/api/lipread/*`.
- На MacBook M3 фраза в 3 секунды распознаётся примерно за 2–4 секунды. На Mac используется процессор: графика (MPS) оказалась медленнее.
- Для русского и казахского подготовлен словарь из 50 слов (`web/src/lipread/words.json`, показан на той же странице). Модели для них пока нет: её нужно обучить на записях этих слов.

Установка (один раз, нужны Python 3.12 и ffmpeg, скачивается около 1,2 ГБ):

```bash
npm run lipread:setup
```

Запуск: `npm run dev` сам стартует сервис, если установка была сделана. Отдельно: `npm run lipread`.

## Результат KRSL-пилота

Данные разделены по людям: P1/P2/P3 — обучение (3614 записей), P4 — валидация (785), P5 — тест (799). 31 файл не прошёл фильтр качества рук. Точность на P5 — **70,09%**; при пороге 0,8 покрытие — **81,23%**, точность принятых ответов — **77,66%**. Это оценка на старых опубликованных координатах, не оценка веб-камеры. Современный Holistic меняет распределение данных; нуждаются в измерении задержка и точность на новых пользователях.

Есть всего один тестовый участник; модель не знает мимики, грамматики и непрерывной речи. Порог не калибровался на неизвестных жестах. Метрики исходных авторов ASL и Easy Sign не выдаются за наши.

## Доступный диалог

Выберите гипотезу распознавания: текст появится на той же странице. Его можно исправить, скопировать, показать крупно или озвучить. Звук включается отдельно кнопкой «Озвучить». Ответ и субтитры доступны в раскрывающемся пункте «Ответ собеседника». Наличие русских/казахских голосов зависит от Windows и браузера. Если нужного голоса нет, приложение сообщает об этом.

«Помочь сформулировать» отправляет только ваш текущий черновик Google после согласия. ИИ предлагает вариант вопроса, а не отвечает вместо преподавателя. Вариант применяется отдельно и автоматически не отправляется. Ключ хранится в корневом `.env.local`, в архив не включён; основной текстовый разговор работает без ключа.

Голосовой ответ в субтитрах использует Web Speech API браузера. Он включается отдельно после согласия, может передавать аудио провайдеру браузера и не гарантирует поддержку kk-KZ. Текстовый ввод работает независимо. В режиме «На устройстве» видео остаётся локальным. Облачное распознавание отправляет выбранный ролик Google после согласия. Слепоглухота этим каналом не покрывается.

## Файлы

- `web/` — приложение и готовая сборка.
- `web/public/models/{krsl,rsl}/` — дополнительные модели, словари, метаданные.
- `web/src/ml/krsl-features.ts` — обработка рук, совпадающая с обучением.
- `tools/train_krsl.py` — воспроизводимое обучение и ONNX-экспорт.
- `server/` — сервер мессенджера: SQL-схема, API, WebSocket, звонки (см. [docs/MESSENGER.md](docs/MESSENGER.md)).
- `tools/serve.mjs` — запуск сервера с готовой сборкой (нужен `npm ci` в корне один раз).
- `docs/krsl/` — список входных файлов с SHA-256 и разделением по участникам.
- `DATA_SOURCES.md`, `THIRD_PARTY_NOTICES.md` — источники, условия и авторство.
- `pipeline/` — неизменённый исходный Python-пайплайн GestureSign для ASL.
